## Before you deploy

### 1. Check for employees with no organisation

The approval fix changes how the reporting manager resolves. Rows with a NULL
`organisation_id` used to silently resolve to *no* manager; they will now resolve
correctly. Worth knowing how many you have:

```sql
SELECT count(*) FROM employees WHERE organisation_id IS NULL;
```

If that is above zero, those people's approval chains have been stalling at stage 1
and needing a staff override. They will start working after this deploy. To see
whether any chain is currently stuck for that reason:

```sql
SELECT i.id, i.subject_type, i.created_at
  FROM approval_instances i
  JOIN approval_instance_stages s ON s.instance_id = i.id AND s.seq = i.current_stage_seq
 WHERE i.status = 'PENDING' AND s.approver_employee_id IS NULL;
```

### 2. Look at what the structure merge will collapse

Departments, designations and levels become organisation-wide. The migration merges
rows that are duplicates *within one organisation* and repoints the people who held
the losing rows. Nothing is deleted that anyone is attached to — holders are moved to
the surviving row first. To see it in advance:

```sql
-- departments that will merge
SELECT c.organisation_id, lower(d.name) AS name, count(*) AS copies
  FROM departments d JOIN companies c ON c.id = d.company_id
 GROUP BY 1,2 HAVING count(*) > 1 ORDER BY 3 DESC;

-- designations that will merge
SELECT c.organisation_id, lower(g.title) AS title, count(*) AS copies
  FROM designations g JOIN companies c ON c.id = g.company_id
 GROUP BY 1,2 HAVING count(*) > 1 ORDER BY 3 DESC;

-- levels that will merge (they collide on the rung number)
SELECT organisation_id, level_no, count(*) AS copies
  FROM org_levels GROUP BY 1,2 HAVING count(*) > 1;
```

If you run a single company per organisation, all three return nothing and the
migration only stamps `organisation_id`.

**Take a database dump first.** The merge is not reversible by re-running anything.

## Deploy

```bash
# on your Mac
git push origin fix/audit-and-org-structure     # or merge to main first

# on the VPS
cd /opt/truehr
git pull
sudo docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Migrations run automatically on boot and are safe to re-run.

Watch the migration output for these two lines:

```
[migrate] structure scoped to organisation — stamped N row(s), merged M duplicate(s), repointed K employee link(s)
[migrate] organisation-wide uniqueness ensured on structure
```

## Still open from the audit

Not fixed, and worth deciding on:

- **The JWT lives in `localStorage`** and lasts seven days with no server-side
  revocation beyond disabling the account. The XSS route to it is closed, but the
  storage choice is still the weak part. Moving to an httpOnly cookie is a real piece
  of work across web and Android.
- **CSP is disabled** (`contentSecurityPolicy: false` in helmet). Worth turning on as
  defence in depth now that uploads are no longer a way through it.
- **`uniq_employees_official_email` is global, not per organisation**, so two tenants
  can never share an email address. Inconsistent with the rest of the tenancy model.
- **The stale Vite tree at `web/src/`** still breaks a local `npm run build`.
  `.dockerignore` hides it from Docker, so deploys are unaffected. Deleting it is safe.
